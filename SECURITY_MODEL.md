# Security Model

Clowder is a trusted-user local MVP. The `Clowder` command starts a YOLO Codex session, but role instructions are behavioral boundaries rather than operating-system isolation. A repository-scoped beta permission profile was tested on Codex `0.155.1`. It enforced the intended filesystem and network boundary, but macOS Seatbelt blocked Keychain authentication for both `gh` and `acli`, so it could not support the required GitHub and Jira workflow.

The MVP protection stack is the versioned local base-branch guard, deterministic Ready for Merge gate, durable gate receipt, deterministic Jira state adapter, required CI evidence, configured review evidence, repository permissions, explicit human gates, and exact target validation for destructive cleanup. The merge receipt is written outside the product repository only after a successful gate, then published unchanged as a pull-request comment and verified before merge. The Jira adapter validates actor, hierarchy, Status, and sole Lifecycle Phase label preconditions. It binds durable intent and completion comments to a request digest, and emits no success receipt until reread Status and Lifecycle Phase match. Reviewer and Tester sessions do not edit product code, but they may create valid Jira Bugs and request state mutations for cards they own under `JIRA_RULES.md`. These are behavioral boundaries, not operating-system isolation.

The Jira adapter is not a server-side compare-and-swap. ACLI performs its read, comment, create, edit, link, and Status transition calls separately. A second writer that bypasses Clowder can race the adapter. The single Active Owner rule, adapter-only Jira writes, immediate rereads, conflict rejection, and idempotent recovery are the compensating controls.

`github.review-evidence` selects the identity strength of review evidence. `clowder-attestation` is the schema-version `1` default for single-account operation. It requires a fresh Reviewer role, versioned Reviewer approval on the reviewed code head, exact attestation binding, final-head CI, and HITL merge approval. It is logical role independence, not cryptographic identity separation. It also blocks any unresolved GitHub change request. `github-approval` retains those controls and additionally requires an approved GitHub review from an identity that GitHub permits to approve the pull request.

The local pre-push guard rejects direct updates and deletions of the configured base branch from each onboarded clone. Git options, another clone, or GitHub's interface can bypass it. Clowder therefore treats the guard as defense in depth and requires HITL to merge only through a pull request after the Ready for Merge gate passes.

Access material never belongs in `.clowder/project.yaml`, prompts, templates, logs, or handoff records. Scripts do not print access material or load local secret files. Production, migration, customer-facing, destructive, and access-material actions require a HITL gate.
